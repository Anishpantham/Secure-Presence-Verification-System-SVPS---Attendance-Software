# Security architecture

## Dynamic presence proof boundary

Policy v2 requires signed QR/audio evidence bound to the student, device, attempt,
session, classroom and current display epoch. QR expiry, single-use audio answers,
server deadlines, serialized playback and idempotency are server enforced.
The faculty playback endpoint, not the student API, exposes the current audio
payload. Raw microphone PCM remains transient on-device.

These controls do not attest capture provenance or physical distance. Current QR
and sound can be recorded/shared/relayed; a five-second deadline is not distance
bounding. Stop/restart invalidates proofs, and mandatory identity/location/required
attestation rules remain. See [the protocol](ACOUSTIC_DYNAMIC_QR.md) and physical
leakage/relay tests. Historical successes must not be retroactively attributed to v2.

## Authentication and authorization

Passwords use Argon2id with memory cost 65,536 KiB, time cost 3 and parallelism 2. Failed logins use a constant-work password check against a dummy hash when the account is absent. Tokens are HS256 JWTs with explicit issuer, audience, type, issued-at, expiry, subject and random ID; the secret must be at least 32 characters and is randomly generated by setup. Access lifetime defaults to 15 minutes. Refresh tokens are random 48-byte URL-safe values stored only as SHA-256 hashes, with a default seven-day lifetime. Rotation is transactional; reused tokens revoke their refresh family.

Logout revokes refresh sessions. Already-issued access tokens remain valid until expiry unless the account is disabled; endpoints check active status and current role on every request. This access-token revocation window is documented, not concealed. Role updates revoke refresh tokens and device bindings and are administrator-only with reasons. The dashboard keeps credentials in memory, so reload requires login. Mobile credentials use OS secure storage.

## Device binding

New registration verifies a password and one-use nonce proof from a native P-256 key. The private key remains inside Android Keystore or iOS Secure Enclave (Keychain for simulator); only canonical SPKI public-key bytes reach the server. Evidence signs exact UTF-8 `idempotency_key + "." + payload` with ECDSA/SHA-256 and a base64 DER signature. Existing HMAC devices remain compatible; new legacy registrations are disabled by default.

The database has a partial unique active-device index. Approved reset revokes old devices; reinstall/key loss cannot silently create a replacement authorized key. Reported hardware backing is not independent key attestation. App Attest verifies a configured pinned chain, app ID, nonce, environment and public key, then checks assertions with a strictly increasing counter. Genuine Apple interoperability and physical-device evaluation remain outstanding. Play Integrity remains unconfigured and fails closed. Never forward a client boolean as a verdict. Full setup and verification limits are in CROSS_PLATFORM_IMPLEMENTATION.md.

## Evidence and decisions

Identity gates precede presence scoring. Enrollment, session, face, challenge and device failures cannot be overridden by a good GPS score. Server-owned rules calculate distance and signal match. A fully outside uncertainty circle rejects; an overlapping boundary requests review. Missing/inaccurate/stale data requests retry or follows the explicit Wi-Fi policy. Mock-location flags reject when reported, but the absence of a flag does not prove an honest OS.

The verified request atomically consumes its challenge, stores an attempt and optionally inserts one attendance record. Retries with the same user/key and exact payload return the original attempt; modified payloads conflict. A different key cannot reuse a consumed challenge. Database locks serialize concurrent retries. Manual corrections are distinct records with actor, reason and before/after status.

## Storage and operations

Fernet protects templates and signing credentials at rest with a dedicated key. Secrets, caches and generated local state are excluded from archives. There is no raw-image retention endpoint. Location summaries are coarse and restricted by role. Production operators should use separate least-privilege migration/runtime database accounts, secret management, key rotation with re-encryption, a retention process, encrypted backups and trusted TLS termination.

Rate buckets live in PostgreSQL, shared across workers. The API does not trust caller-supplied forwarded headers for rate identity; behind a reverse proxy, connection IP limits can group multiple clients. Account limits remain independent. Configure trusted proxy handling and infrastructure limits for deployment. Bounded request bodies, decoded image dimensions and model serialization reduce resource abuse but do not replace load testing or upstream request throttling.

Audit rows are append-only through ordinary application APIs except their reviewed flag. A database administrator can still alter them: this is not tamper-proof external audit storage. Implement a protected external append-only sink if that is an institutional requirement.


## Cross-platform completion update

New clients use native non-exported P-256 keys and proof of possession. Android hardware backing is queried locally; physical iPhones require Secure Enclave and simulators use device-only Keychain. Storage metadata alone is not server-verified hardware attestation. App Attest verification enforces a configured pinned Apple root, app identity, nonce, environment, key binding and increasing assertion counter. Synthetic certificates verify logic only; actual Apple-provider acceptance remains unverified. Android Play Integrity remains fail closed. Legacy HMAC registration is disabled by default, existing keys migrate through audited resets. Exact enrollment retries recover a lost HTTP response without permitting different replay payloads. Required attestation cannot be replaced by a favorable GPS score.


Policy v2 retires the iOS gps_only option. Current iOS choices are review, retry and dynamic; the migration maps an existing gps_only choice to dynamic while retaining stricter review/retry settings. Dynamic requires completed QR/audio proof alongside mandatory identity/device/GPS gates; a global requirement for attestation still applies. The local review policy was not changed. QR/audio does not independently attest a platform or sensor and can be relayed. See [the protocol](ACOUSTIC_DYNAMIC_QR.md).
